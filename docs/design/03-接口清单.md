# 《REST 与 WebSocket 接口清单》——Web 组态实时监控大屏（开源核心 P0）

> 专项定位：本文档是接口层唯一契约，供前后端并行开发直接依据。命名沿用 `mvp-first` 骨架；凡偏离骨架处在下节显式列出。阶段标注：**[P0]** 开源核心必做；**[P1]** 二期补齐（接口现在定死，届时只做实现不破坏契约）。

---

## 0. 与骨架的差异（先声明，后文以此为准）

| # | 差异点 | 骨架原设计 | 本清单定稿 | 理由 |
|---|---|---|---|---|
| 1 | 路径前缀 | `/api` | `/api/v1`；运行态 WS 端点统一 `/api/v1/ws/runtime` | 任务要求版本化前缀，后续 schemaVersion 演进不动旧路由 |
| 2 | 乐观锁 | `baseUpdatedAt`（ISO 时间戳） | `baseRevision`（整数版本号），不符返回 409 `REVISION_CONFLICT`，成功响应返回新 revision | 任务明确"版本号"；毫秒时间戳存在同毫秒碰撞与时区歧义。`projects` 表增 `revision` 列（初始 1，每次保存 +1），不写入 doc 内部 |
| 3 | 发布模型 | 分享链接直接读 live doc | `share_links.doc_snapshot`（JSONB 快照）：创建/refresh 时冻结脱敏后 doc；"发布"语义 = 创建或刷新分享链接；无 publish 状态机、无 `published_doc` 列 | 裁决：避免编辑半成品直透线上大屏，快照随 token 走、与工程 doc 解耦；公开端与管理面读写分离（路径单复数差异为有意设计，见 2.5 声明） |
| 4 | 变量换算位置 | `Binding.transform`（前端 binder 求值） | `VariableDef.scale / offset / precision`，**服务端采集入池前一次性求值** | 评审移植项：显示值、WS 帧、报警阈值三者同口径（工程值），消除"界面显示 72.5 但按 725 判阈值"的分叉。Binding 层只保留表现层映射（`mapping: {kind:'enum', map: Record} | {kind:'range', bands:[{min,max,value}]}`，实现颜色/显隐，结构以《工程 JSON 数据结构》§2.8 为准），Binding 上不存在任何数值换算字段 |
| 5 | 新增接口 | — | `health`、`logout`、`PUT auth/password`、独立的 `export`/`import` 端点、`datasources/test`、`variables/values`（编辑器调试值快照）、`shares/{token}/refresh`、`alarms/ack`(P1) | 评审指出的共同缺陷修正（健康检查、改密、连通性测试、凭证脱敏出口）+ 裁决增补（编辑器调试值快照、快照刷新端点） |
| 6 | 公开报警 REST | 骨架 #12 公开 alarms 接口 | **取消**，由 WS `snapshot` 帧内嵌 `activeAlarms` 覆盖 | 连接建立即推活动报警，消除 REST 补齐的时序窗口；编辑器侧报警列表走 Bearer 接口 |
| 7 | mock 开关 | — | mock 为数据源类型之一（`DataSource.type='mock'`），其 `enabled` 字段即开关；不设 `projects.mock_enabled` 列、不设独立 mock REST | 裁决：开关随数据源配置入 doc、随导出，不设独立端点与表列 |
| 8 | WS 订阅帧 | 仅"预留 subPages" | P0 **无 subscribe 帧**：连接建立即整工程订阅（连接 URL 的 `project` 参数锁定工程与订阅范围）；按页订阅（`subPages` 帧）为 P2 规模化预留，届时再定义帧结构 | 裁决：P0 规模（≤50 连接、≤5000 变量）下按页裁剪无收益、徒增协议复杂度；切页为纯前端渲染行为 |

## 1. 全局约定

### 1.1 基础
- Base URL：`https://{host}/api/v1`；本地开发 `http://localhost:8000/api/v1`（Vite dev 代理 `/api`）。
- 请求/响应：`application/json; charset=utf-8`，文件下载除外。
- 时间格式：REST 一律 ISO8601 UTC（`2026-01-15T08:30:00.000Z`）；WebSocket 帧内一律 epoch 毫秒（`1760000000000`）。
- ID 规则：DB 主键（`users`/`projects`/`share_links`）为服务端生成 UUID（`alarm_records` 主键为 BIGSERIAL 自增）；doc 内部对象 id 由前端 nanoid 生成、导入时保留，建议前缀（惯例、非校验项）：页面 `page_`、组件 `cmp_`、变量 `var_`、数据源 `ds_`、绑定 `bnd_`、报警规则 `alm_`；分享 token 为裸 nanoid(21)；工程 `doc.project.id` = DB UUID（导入时由服务端重新生成并回写 doc）。
- 变量字段名：`key`（全局唯一标识）+ `label`（显示名）；运行态帧与报警记录以 `variable.key` 标识变量。

### 1.2 鉴权
- 编辑器侧：`Authorization: Bearer <access_token>`。PyJWT HS256，有效期 2h，密钥 `.env:JWT_SECRET`。管理员账号由初始化脚本按 `.env:ADMIN_USER/ADMIN_PASSWORD` 创建，无注册接口。
- 分享侧：share token 本身即凭证（无状态，可设过期、可停用）。
- **角色（M8 修订）**：`users.role ∈ admin | operator | viewer`（alembic 0002，存量置 admin）。admin=用户管理/审计/全部工程读写；operator=工程读写/反控/报警 ack/连通性测试；viewer=只读+预览。分享 token 不变（token 即凭证，只读）。写操作（工程 PUT/DELETE、反控、ack、用户管理）按角色校验，不足 403 `FORBIDDEN`。
- 401 统一语义：token 缺失/过期/非法，前端清除本地 token 跳登录页。

### 1.3 错误响应统一信封

```json
{"code": "REVISION_CONFLICT", "message": "文档已被他人修改", "currentRevision": 8}
```

- HTTP 状态码定位错误类别；`code` 为字符串业务错误码（如 `REVISION_CONFLICT`）；`message` 中文可直接展示；可选扩展字段随错误类型附加（如 409 时的 `currentRevision`）。
- 校验失败统一 422，错误体 `{code, message, errors: [{path, message}]}`，**不设 400/422 双口径**：

```json
{
  "code": "validation_error",
  "message": "校验失败",
  "errors": [
    {"path": "pages[0].components[2].bindings[0].variableId", "message": "变量 v_temp_01 不存在"},
    {"path": "variables[1].datasourceId", "message": "数据源 ds_mqtt_01 不存在"}
  ]
}
```

### 1.4 分页约定
`?page=1&size=20`（page 1 起始，size 默认 20 上限 100），响应 `{total, page, size, items}`。

### 1.5 量化规模上限（验收基线，写入部署文档）
- 单机 2C4G、server 单 worker；浏览器 WS 并发 ≤50；单工程变量 ≤5000；单页组件 ≤200；doc 体积 ≤1MB 编辑器 UI 告警、>2MB 服务端 422（`code=doc_too_large`）；值刷新 500ms~1s 级；保存防抖 3s。

### 1.6 安全与兼容基线
- 全链路 HTTPS；Nginx access log 对 `/api/v1/ws/` 路径**去除 query**（token 走查询串的脱敏补偿），本条为统一部署基线。
- 浏览器基线：Chrome/Edge ≥ 90，不支持 IE（原生 WebSocket、CSS transform 动画的版本下限）；不使用 `structuredClone`（Vite target es2020，深拷贝用自写 util）。
- 公开面防护：同一 share token 并发运行态 WS ≤20（`SHARE_MAX_WS_PER_TOKEN`）；同一用户对同一工程 JWT 运行态 WS ≤10（`JWT_WS_MAX_PER_USER_PROJECT`）；同 IP+token 拉取分享文档 ≤30 次/分钟（超限 429）；登录同用户名连续失败 5 次锁 60s（内存计数）。

### 1.7 数据边界声明（接口层契约）
- 数据源载荷仅支持 JSON（对象/数组/标量，点路径 `jsonPath` 取值）；**CSV、十六进制、二进制上报不支持**（企业版评估），现场对接前须声明。
- MQTT 采集默认 **QoS 0 + clean session=true**（不回放离线消息，防重连值风暴与告警误判）；QoS 1 为数据源可选配置，clean session 恒为 true。client id：`webscada-{projectId}-{nanoid8}`。
- 时间戳信任策略：数据源级可选 `config.tsPath` 指定载荷时间戳点路径，缺省用服务端接收时间；配置了 `tsPath` 时取该路径值（epoch ms），缺失、非法、或与服务器时间偏差超过 ±300s（双向，含未来时间）时视为不可信，以服务器接收时间为准并记 warn。stale 判定：距今 > `staleTimeoutMs`（默认 3×采集周期，最小 5s）→ `q='stale'`。
- 报警记录保留：默认 30 天（`ALARM_RETENTION_DAYS`）+ 单工程行数上限 200000（`ALARM_MAX_ROWS_PER_PROJECT`），server 进程内每 24h 执行清理（启动时先跑一次，见《工程 JSON 数据结构》§4.4）；server 启动将遗留 `active` 记录收口为 `recovered`。

## 2. REST 接口清单

### 2.1 健康检查

#### GET /api/v1/health 【P0】
- 鉴权：公开（compose healthcheck 用）。
- 入参：无（`?deep=1` 时附带 DB `SELECT 1` 探测）。
- 出参 200：

```json
{"status": "ok", "version": "0.1.0", "uptimeSec": 3721, "db": "ok"}
```

- 错误：503 `{"status":"degraded","db":"error"}`。

### 2.2 认证

#### POST /api/v1/auth/login 【P0】
- 鉴权：公开。
- 入参：

```json
{"username": "admin", "password": "••••••"}
```

- 出参 200：

```json
{"access_token": "eyJhbGciOiJIUzI1NiJ9...", "token_type": "bearer", "expires_in": 7200}
```

- 错误：401 用户名或密码错误（统一文案防枚举）；429 连续失败锁定（60s）。

#### POST /api/v1/auth/logout 【P0】
- 鉴权：Bearer。
- 语义：无状态 JWT 主动失效——服务端将当前 token 的 `jti` 加入进程内黑名单（保留至其 exp；单 worker 下进程重启黑名单清空，残留 token 寿命 ≤2h，可接受，写入文档）。前端同时清除本地 token。
- 出参：204。
- 错误：401。

#### GET /api/v1/auth/me 【P0】
- 鉴权：Bearer。
- 出参 200：

```json
{"id": "3c4d5e6f-7a8b-4c9d-8e1f-2a3b4c5d6e7f", "username": "admin", "createdAt": "2026-01-10T02:00:00.000Z"}
```

- P0 无角色概念（`users` 表无 role 列；单团队所有登录用户均为管理员；P2 角色权限届时迁移扩展，本期不建列）。
- 错误：401。

#### PUT /api/v1/auth/password 【P0】
- 鉴权：Bearer。
- 入参：`{"oldPassword": "...", "newPassword": "..."}`，newPassword 最少 8 位。
- 出参：204。
- 语义：bcrypt 校验旧密码后更新哈希；**旧 token 仍有效至 exp（≤2h）**，P0 不做全局 token 作废，写入文档声明。
- 错误：422 旧密码错误（`code=invalid_old_password`）；422 新密码强度不足（统一 422 口径，见 1.3）。

#### POST /api/v1/auth/refresh 【P1】
- 鉴权：Bearer（未过期 token 换新 token）。
- 出参 200：同 login。7x24 大屏 P0 一律走分享链接（share token 无 2h 限制）；编辑器内预览受 JWT 2h 限制，P1 提供 refresh。

### 2.3 工程管理

#### GET /api/v1/projects 【P0】
- 鉴权：Bearer。入参：`?keyword=&page=&size=`。列表**不含 doc**。
- 出参 200：

```json
{
  "total": 12, "page": 1, "size": 20,
  "items": [
    {"id": "9b2f3c4d-5e6f-4a7b-8c9d-0e1f2a3b4c5d", "name": "1号车间产线", "description": "装配线监控",
     "revision": 7, "updatedAt": "2026-01-14T06:10:00.000Z"}
  ]
}
```

- 错误：401。

#### POST /api/v1/projects 【P0】
- 鉴权：Bearer。
- 入参：`{"name": "新建工程", "description": ""}`。P0 不允许创建时携带完整 doc（导入走 2.4 专用端点）。
- 行为：服务端生成空白 doc（当前 `schemaVersion` + 默认 `settings` + 一个 1920x1080 默认页面），`revision=1`。
- 出参 201：`{"id": "1a2b3c4d-5e6f-4a7b-8c9d-0e1f2a3b4c5e", "name": "新建工程", "revision": 1, "updatedAt": "..."}`
- 错误：422（name 为空或超 128 字符等校验失败，附 `errors`；上限与《工程 JSON 数据结构》§2.13 规则 6 一致）。

#### GET /api/v1/projects/{id} 【P0】
- 鉴权：Bearer。
- 出参 200：

```json
{
  "id": "9b2f3c4d-5e6f-4a7b-8c9d-0e1f2a3b4c5d", "name": "1号车间产线", "description": "装配线监控",
  "revision": 7,
  "createdAt": "2026-01-10T03:00:00.000Z", "updatedAt": "2026-01-14T06:10:00.000Z",
  "doc": {"...": "完整 ProjectDoc，结构见《工程 JSON 数据结构》专项"}
}
```

- 错误：404。

#### PUT /api/v1/projects/{id} 【P0】
- 鉴权：Bearer。工程配置**整体保存**唯一入口（编辑器 3s 防抖提交）。
- 入参：

```json
{"doc": {"...": "完整 ProjectDoc"}, "baseRevision": 7}
```

- 服务端流水线：`schemaVersion` 校验（必须**等于**当前支持版本，不符 422 `code=version_unsupported`；迁移唯一实现点为前端 `migrateDoc()`，服务端不实现迁移）→ doc 体积校验（>2MB 422 `code=doc_too_large`）→ Pydantic v2 全量校验 → **引用完整性校验**（见 4.2）→ 覆盖 `doc`、`revision+1` → 热更新采集任务与报警规则集（按 datasource/variable 差量重建，在线 WS 连接保持不断开）。
- 出参 200（返回新 revision）：`{"revision": 8, "updatedAt": "2026-01-14T06:12:33.000Z"}`
- 错误：409 `REVISION_CONFLICT`（附 `currentRevision`）；422（`version_unsupported` / `doc_too_large` / 校验或引用失败，附 `errors`）；404。

#### DELETE /api/v1/projects/{id} 【P0】
- 鉴权：Bearer。
- 级联：share_links 删除；alarm_records 删除；**运行态级联**见 4.3 矩阵（在线 WS 收 `error(PROJECT_REMOVED)` 帧后关闭、采集任务停止、内存变量池与未恢复报警态释放）。
- 出参：204。错误：404。

### 2.4 导入 / 导出

#### GET /api/v1/projects/{id}/export 【P0】
- 鉴权：Bearer。
- 出参 200：`Content-Type: application/json`，body 为 `ProjectDoc`；**响应头不使用非 ASCII 文件名**——由前端以 Blob 触发下载并按工程名命名文件。
- **凭证脱敏**：`mqtt.config.password` 置空、`rest`/`websocket` 的 `headers` 中敏感键（`authorization`/`password`/`token`/`secret`/`key`）置空；`username` 不脱敏（库内凭证 Fernet 加密存储，`cryptography`，密钥 `.env: DATASOURCE_SECRET`；所有出口统一脱敏）。导入后用户需重新填写凭证，文档明示。
- 错误：404。

#### POST /api/v1/projects/import 【P0】
- 鉴权：Bearer。
- 入参：multipart 文件上传，或 JSON body `{"doc": {"...": "导出文件内容原样粘贴"}}`（前端 FileReader 读文件后 POST JSON）。
- 服务端流水线：`schemaVersion` 校验（必须等于当前支持版本，不符 422 `code=version_unsupported`；迁移唯一实现点为前端 `migrateDoc()`，服务端不做迁移）→ 凭证处理（**导入文件中凭证一律视为空，需重填**）→ Pydantic 校验 → 引用完整性校验 → 重新生成**新** DB UUID 并回写 `doc.project.id`（doc 内部对象 id 保留，工程内唯一即可）→ 创建工程 `revision=1`。导入不覆盖已有工程。
- 出参 201：`{"id": "2b3c4d5e-6f7a-4b8c-9d0e-1f2a3b4c5d6f", "name": "1号车间产线", "revision": 1, "updatedAt": "..."}`
- 错误：422（`version_unsupported` / `doc_too_large` / 校验或引用失败，附 `errors`）。
- **round-trip 契约（pytest 必过项）**：导出 → 导入 → 再导出，除 `doc.project.id`、`createdAt/updatedAt`、被脱敏的凭证字段外，diff 为空；用例必须覆盖"清除凭证后导出导入"。

### 2.5 发布模型声明（快照方案）

- **无 `publish`/`unpublish` 状态机、无 `projects.published_doc` 列**（原方案废弃）。
- "发布"语义 = **创建或刷新分享链接**：创建（`POST /api/v1/projects/{id}/shares`）或刷新（`POST /api/v1/shares/{token}/refresh`）时，将工程当前 `doc` 脱敏后冻结为 `share_links.doc_snapshot`；工程 doc 后续修改不影响已建快照，需 refresh 才更新。
- 公开端与管理面读写分离，**路径单复数差异为有意设计**：
  - 公开端（无鉴权，token 即凭证）：`GET /api/v1/share/{token}`（单数：读快照）；
  - 管理端（Bearer）：`GET|POST /api/v1/projects/{id}/shares`（复数：列表/创建）、`DELETE /api/v1/shares/{token}`、`POST /api/v1/shares/{token}/refresh`。

### 2.6 分享链接

#### POST /api/v1/projects/{id}/shares 【P0】（创建 = "发布"）
- 鉴权：Bearer。
- 语义：以工程当前 `doc` 冻结脱敏快照写入 `share_links.doc_snapshot`（脱敏规则同 2.4 导出）。
- 入参：`{"expiresAt": null}`（可选；ISO8601 或 null 永不过期；进入页面恒为快照 doc 的第一个页面）。
- 出参 201：

```json
{
  "token": "V1StGXR8_Z5jdHi6B-myT",
  "url": "https://host/s/V1StGXR8_Z5jdHi6B-myT",
  "expiresAt": null, "revokedAt": null,
  "createdAt": "2026-01-14T07:01:00.000Z"
}
```

- 错误：404；422。

#### GET /api/v1/projects/{id}/shares 【P0】
- 鉴权：Bearer。
- 出参 200：

```json
{"items": [
  {"token": "V1StGXR8_Z5jdHi6B-myT", "url": "https://host/s/V1StGXR8_Z5jdHi6B-myT",
   "expiresAt": null, "revokedAt": null,
   "createdAt": "2026-01-14T07:01:00.000Z", "lastAccessAt": "2026-01-15T09:00:00.000Z"}
]}
```

- `lastAccessAt` 用于泄露排查，首次访问前为 null。

#### POST /api/v1/shares/{token}/refresh 【P0】（"发布"的刷新语义）
- 鉴权：Bearer。
- 语义：以工程当前 `doc` 重新冻结脱敏快照覆盖 `doc_snapshot`；并向该 token 的在线 WS 连接广播 `reload` 帧（见 3.4），线上大屏自动换版。
- 入参：无。
- 出参 200：`{"token": "V1StGXR8_Z5jdHi6B-myT", "refreshedAt": "2026-01-14T08:00:00.000Z"}`
- 错误：404（token 不存在或已撤销）。

#### DELETE /api/v1/shares/{token} 【P0】
- 鉴权：Bearer。

### 2.7 报警

#### GET /api/v1/projects/{id}/alarms 【P0】
- 鉴权：Bearer。入参：`?status=triggered|acked|cleared&level=info|warn|critical&variableKey=&from=&to=&page=&size=`（**M8 修订**：status 值域随单行状态机更新；`status` 缺省=`triggered,acked`（未恢复集合）；`variableKey` 前缀匹配；`from/to` 为 ISO8601 UTC 区间（按 triggered_at 过滤）；分页见 1.4），按 `triggeredAt` 倒序。
- 出参 200：

```json
{
  "total": 3, "page": 1, "size": 20,
  "items": [
    {"id": 1024, "ruleId": "r_01",
     "variableKey": "temp_01",
     "level": "critical", "message": "1号反应釜温度超高: 82.5 ℃",
     "value": "82.5", "status": "active",
     "triggeredAt": "2026-01-15T08:30:00.000Z", "recoveredAt": null}
  ]
}
```

- `variableKey`/`value` 为触发时快照（规则/变量被删后历史仍可读）；`value` 为**工程值**字符串快照（变量级换算后），与 WS 帧、界面显示同口径。
- **M8 单行状态机**：`status ∈ triggered | acked | cleared`（触发→确认→恢复；恢复不再另插新行，`clearedAt` 取代 `recoveredAt`）。列表条目新增 `ackedAt / ackedBy / ackedNote / clearedAt`（均可空）。兼容期保留 `GET /projects/{id}/alarm-records` 为废弃别名（同实现），前端一律改用 `/alarms`。旧前端上报端点 `POST /projects/{id}/alarm-records` 保留兼容：active/recovered 上报映射为状态机 trigger/clear。
- 恢复语义：server 启动时，将遗留 `active` 记录批量置 `recovered`（`recoveredAt=启动时刻`），防僵尸活动报警。

#### POST /api/v1/projects/{id}/alarms/{alarmId}/ack 【M8 已落地】
- 鉴权：Bearer；角色 operator/admin（viewer 403）。
- 入参：`{"note": "处理说明（可选，≤256 字符）"}`。
- 出参 200：`{"id": 1024, "status": "acked", "ackedAt": "2026-01-15T08:31:00.000Z", "ackedBy": "3c4d5e6f-...", "ackedNote": "已派单"}`
- 语义（单行状态机）：`triggered→acked`；`cleared` 后补确认只填 ack 字段、status 保持 `cleared`；`acked` 重复 ack 幂等返回当前状态。同时向该工程在线 WS 广播 `alarmAck` 帧（S→C：`{"type":"alarmAck","alarmId":1024,"ackedAt":...}`，M8 增补帧）。落审计 `alarm_ack`。

- 报警声音/级别等设置存 `doc.settings.alarm`，随工程 doc 整体 PUT 保存（见 2.3），**不设独立 alarm-settings 端点**；运行页的本地静音开关是客户端覆盖，写 localStorage，不上报服务端。

## 3. WebSocket 运行态通道

### 3.1 连接 URL 与鉴权

```
wss://{host}/api/v1/ws/runtime?project={projectId}&token={JWT|shareToken}&page={pageId?}
```

- **token 走查询串**：浏览器原生 WebSocket 无法携带自定义 Header，这是固定栈下的唯一选择；传输安全依赖 HTTPS。**部署基线**：Nginx 对 `/api/v1/ws/` 路径的 access log 去除 query（或整条不记 query），防 token 入日志。
- token 二选一：
  - **JWT**（编辑器预览、编辑器内全屏大屏）：校验签名与有效期；
  - **shareToken**（分享链接 / iframe）：校验存在、未撤销（`revoked_at` 为空）、未过 `expiresAt`；读取 `doc_snapshot` 快照。
- `page` 参数 P0 仅记录（整工程订阅，切页为纯前端行为）；P2 `subPages` 生效后作为初始页集合。
- 鉴权失败**不做握手阶段分支化 HTTP 拒绝**（Starlette accept 前 close 只能 403，浏览器侧只会看到 1006）：统一 accept 后立即推 `error` 帧再 close（close code 统一 4000，具体原因只看帧 `code`，见 3.3）。

### 3.2 连接建立序列

1. HTTP Upgrade，token 校验通过；
2. 连接注册进 `ws_manager`；并发上限检查：同一 share token 运行态 WS ≤20（`SHARE_MAX_WS_PER_TOKEN`）、同一用户对同一工程 JWT WS ≤10（`JWT_WS_MAX_PER_USER_PROJECT`），超限推 `error(RATE_LIMITED)` 后 close；
3. 服务端**立即推送**：`snapshot`（内嵌当前活动报警 `activeAlarms`，客户端无需再调 REST 补齐，消除时序窗口）；
4. 此后持续推送：`values`（100ms 合帧 + 变化抑制）、`alarm` / `alarmClear`（即时帧）、`ping`、`reload`。

### 3.3 关闭语义与 error 帧 code 定义

**close code 统一 4000，具体原因只看 error 帧 `code`**：

| error 帧 code | 含义 | 客户端行为 |
|---|---|---|
| TOKEN_EXPIRED | JWT 非法/过期 | 停止重连；JWT 引导重新登录，分享页重新校验链接 |
| PROJECT_REMOVED | 工程不存在或已删除 | 停止重连 |
| SHARE_REVOKED | 分享链接已撤销 | 停止重连，页面显示"链接已失效" |
| SHARE_EXPIRED | 分享链接已过期 | 停止重连，页面显示"链接已失效" |
| RATE_LIMITED | 并发连接数超限 | 停止重连，提示连接数已达上限 |
| PROJECT_MISMATCH | （P2 预留：按页订阅引入后使用；P0 无订阅帧，不会出现） | **唯一不关闭连接的例外**，连接保持 |
| INTERNAL_ERROR | 服务端内部错误 | 按网络级失败处理：指数退避重连 |

- 客户端总则：收到致命 code（上表除 `PROJECT_MISMATCH`/`INTERNAL_ERROR` 外）→ 停止重连并提示人工介入；网络级失败（建连失败、心跳判死、非正常关闭）→ 指数退避重连（1s 起、上限 30s，见 3.6）。

### 3.4 帧目录与完整 JSON 示例

统一为 JSON 文本帧（UTF-8）；除 `alarm`/`alarmClear`/`error`/`reload` 为即时帧外，`values` 走 100ms 合并窗口（单连接值帧上限 10 帧/秒）。变量在帧内以 `variable.key` 标识。

#### S→C snapshot 【P0】连接建立后一次性全量当前值 + 内嵌活动报警

```json
{
  "type": "snapshot",
  "ts": 1760000000000,
  "data": {
    "reactor1_temp": {"v": 63.2, "q": "good",  "t": 1759999999800},
    "pump1_run":     {"v": true, "q": "good",  "t": 1759999999800},
    "flow_01":       {"v": null, "q": "stale", "t": 1759999000000}
  },
  "activeAlarms": [
    {"id": 1024, "ruleId": "r_01", "variableKey": "temp_01", "level": "critical",
     "message": "1号反应釜温度超高: 82.5", "value": "82.5", "status": "active",
     "triggeredAt": 1759999000000}
  ],
  "totalActive": 1,
  "truncated": false
}
```

- `v` 为**工程值**：变量级 `scale/offset/precision` 已在服务端采集入池前一次性求值（差异声明 #4）；`bad` 质量时 `v=null`。
- `q ∈ good | stale | bad`：质量位，前端据此灰显/标记数据不可信。
- `data` 的键为变量 `key`。
- `activeAlarms`：连接时刻未恢复报警（结构同 2.7 REST 报警列表条目，时间戳为 epoch 毫秒）；防风暴上限 200 条，超出按 `critical > warn > info` 优先保留并置 `truncated=true`；前端报警列表 UI 封顶 200 并提示"还有 N 条未显示"。

#### S→C values 【P0】值增量

```json
{"type": "values", "data": {"reactor1_temp": {"v": 63.8, "q": "good", "t": 1760000000500}}}
```

- 100ms 合并窗口、仅含**变化变量**、值无变化不下发（变化抑制）。
- 客户端收到未知 `key`（保存后变量集变化）必须**忽略**，等下次连接 snapshot 对齐。

#### S→C alarm 【P0】报警触发（即时帧，不合并）

```json
{
  "type": "alarm",
  "alarm": {
    "id": 1025, "ruleId": "r_02", "variableKey": "press_01", "level": "warn",
    "message": "主管道压力偏高: 0.86 MPa", "value": "0.86",
    "status": "active", "triggeredAt": 1760000010000
  }
}
```

#### S→C alarmClear 【P0】报警恢复（即时帧）

```json
{"type": "alarmClear", "alarmId": 1024, "recoveredAt": 1760000060000}
```

#### S→C ping / C→S pong 【P0】心跳

```json
{"type": "ping"}
{"type": "pong"}
```

#### C→S write 【M8 增补】反控写请求

```json
{"type": "write", "reqId": "w_01", "variableKey": "pump1_running", "value": true}
```

- 鉴权：JWT 连接（operator/admin 角色）；share token 连接收到 write 一律回 `writeAck(ok=false, code=READ_ONLY)`。
- 服务端校验：变量存在、`writable=true`、角色足格；按数据源类型分发（mqtt publish / rest POST / 上游 ws send；mock 服务端回环）。

#### S→C writeAck 【M8 增补】写结果回执（即时帧）

```json
{"type": "writeAck", "reqId": "w_01", "ok": true}
{"type": "writeAck", "reqId": "w_02", "ok": false, "code": "NOT_WRITABLE", "message": "变量 pump1_running 未开启可写"}
```

- `code ∈ NOT_WRITABLE | READ_ONLY | FORBIDDEN | VARIABLE_NOT_FOUND | WRITE_FAILED`；成功写透后值随下一帧 `values` 广播。

#### S→C alarmAck 【M8 增补】报警确认广播（即时帧）

```json
{"type": "alarmAck", "alarmId": 1024, "ackedAt": 1760000020000, "ackedBy": "admin"}
```

- 任意用户经 REST ack 成功后向该工程全部在线连接广播，前端据此更新列表确认态（无需轮询）。

#### C→S 按页订阅（subPages）【P2 预留，P0 不实现】

P0 无任何客户端订阅帧：连接建立即整工程订阅（`project` 查询参数锁定）。P2 规模化时引入 `subPages` 帧按页裁剪 `values`/`alarm` 下发，帧结构届时定义，不占用现有帧类型；`PROJECT_MISMATCH` error code 为其预留。

#### S→C error 【P0】重大事件通知，默认随后主动 close

```json
{"type": "error", "code": "SHARE_REVOKED", "message": "分享链接已撤销，连接即将关闭"}
```

- `code ∈ TOKEN_EXPIRED | PROJECT_REMOVED | SHARE_REVOKED | SHARE_EXPIRED | RATE_LIMITED | PROJECT_MISMATCH（不关闭连接） | INTERNAL_ERROR`，close code 统一 4000（见 3.3）。

#### S→C reload 【P0】快照刷新通知（独立帧，不用 error）

```json
{"type": "reload"}
```

- 触发：该 token 的分享快照被刷新（`POST /api/v1/shares/{token}/refresh`，见 2.6）。
- 客户端动作：重新拉取文档（分享连接 GET `/api/v1/share/{token}`），重建页面渲染；已收到的变量值缓存保留，实现"刷新分享快照后线上大屏自动换版"。预览连接不依赖此帧（编辑保存后前端本地已持新 doc）。

### 3.5 心跳与超时

| 方 | 规则 |
|---|---|
| 服务端 | 每 20s 发 `ping`，连续 2 次（40s）未收到 `pong` 判死并 close（不发 error 帧，客户端按网络级失败退避重连） |
| 客户端 | 30s 未收到**任何**入站帧 → 判定假死（覆盖 TCP 半开/服务端宕机），主动断开并重连 |

### 3.6 断线重连语义

- 网络级失败（建连失败/心跳判死/非正常关闭）指数退避：1s 起步 ×2，上限 30s，附加 ±20% 抖动防雪崩；收到致命 error code（`TOKEN_EXPIRED`/`PROJECT_REMOVED`/`SHARE_REVOKED`/`SHARE_EXPIRED`/`RATE_LIMITED`）停止重连，提示人工介入。
- 重连成功后服务端重发 `snapshot`（内嵌 `activeAlarms`）；客户端**本地不清数据，整体覆盖**恢复一致性。
- 服务端重启：客户端静默检测触发重连；服务端 lifespan 重启采集与规则引擎，遗留 `active` 报警记录启动时置 `recovered`（见 2.7），重启期间实时值不落库，恢复连接后由各数据源重新采集填充，此前前端按 `stale` 呈现。

### 3.7 多页面 / 多工程订阅切换

- **同工程切页**：P0 为手动页签切换 + 整工程订阅，切页是纯前端渲染行为（切换 Page），**不发送任何帧**（自动轮播为 P1 预留，P0 不做）；P2 大工程可用 `subPages` 按页裁剪减流量。
- **多工程**：一条连接绑定一个工程（连接时以 `project` 参数锁定）；同屏看多工程开多条 WS，总量受 50 连接基线约束。P0 不提供跨工程单连接。
- 报警与页面关系：P0 全量订阅下，全部页面的报警帧统一下发，报警列表不分页聚合（含后台页报警，符合产线监控预期）；P2 按页订阅后，仅下发订阅页集合内绑定变量的报警。

### 3.8 与编辑器预览的关系

- 编辑器"预览"按钮与运行态**共用 `RuntimeView` 与同一 WS 端点**，仅 token 不同（JWT），区别在数据面：
  - 预览：读 **live doc** + live 值 + live 报警（快照方案下无发布状态概念）；编辑保存后前端本地已持新 doc，无需服务端通知；
  - 分享/iframe：读 **`share_links.doc_snapshot` 快照**，`reload` 帧驱动换版，与编辑器改动完全隔离。
- 编辑器保存（PUT）不中断预览 WS 连接：采集任务与规则集差量热更新，值流持续；变量集变化后客户端按 3.4 `values` 规则忽略未知 `key`，下次重连 snapshot 对齐。

### 3.9 报警链路接口语义（协议级声明）

1. **判定基准**：报警阈值按**工程值**判定（变量级换算在服务端采集入池前一次性完成），界面显示值、`values`/`snapshot` 帧、报警 `value` 三者同源同口径；本条写入组件协议与告警配置文档，用户界面配置阈值时看到的提示语为"按显示值判定"。
2. **报警变色优先级**：静态 props < 绑定映射（`mapping: {kind: 'enum'|'range'}`） < 报警态；报警态覆盖组件填充色并叠加闪烁动画（level 对应色），恢复后自动回落到绑定求值结果；`visibility` 绑定优先于报警（隐藏即隐藏）。此规则为组件渲染层唯一实现点 `widgets/WidgetHost.vue`，消除双链路歧义。
3. **防风暴**：同一规则前端提示音 60s 节流（`doc.settings.alarm.soundThrottleSec` 可配）；`snapshot` 内嵌 `activeAlarms` 封顶 200 条（超出按 `critical > warn > info` 优先保留）；`alarm` 单帧始终发送保实时性，超限时前端列表封顶并提示。

## 4. 横切契约

### 4.1 涉及的存储变更（供 models/alembic 专项对齐）

```sql
users(id UUID pk, username TEXT UNIQUE, password_hash TEXT, created_at TIMESTAMPTZ)
projects(id UUID pk, name TEXT, description TEXT, doc JSONB,
         revision INT NOT NULL DEFAULT 1,      -- 乐观锁版本号（差异 #2）
         owner_id UUID FK users,
         created_at TIMESTAMPTZ, updated_at TIMESTAMPTZ)
share_links(id UUID pk, project_id UUID FK, token TEXT UNIQUE,
            doc_snapshot JSONB,                -- 分享快照（差异 #3）：创建/refresh 时冻结脱敏后 doc
            expires_at TIMESTAMPTZ NULL, revoked_at TIMESTAMPTZ NULL,
            last_access_at TIMESTAMPTZ NULL, created_at TIMESTAMPTZ)
alarm_records(id BIGSERIAL pk, project_id UUID FK, rule_id TEXT,
              variable_key TEXT,               -- 触发时快照（规则/变量被删后历史仍可读）
              value TEXT,                      -- 触发时字符串快照（工程值口径）
              level TEXT, message TEXT,
              status TEXT /* active|recovered */,
              triggered_at TIMESTAMPTZ, recovered_at TIMESTAMPTZ NULL)
-- 索引：share_links(token)、alarm_records(project_id, triggered_at DESC)、projects(owner_id)
```

- 凭证加密：数据源凭证字段库内 Fernet 加密（`cryptography`，密钥 `.env: DATASOURCE_SECRET`），接口出口一律脱敏（见 2.4）。
- 不设 `projects.mock_enabled` 列、不设 `projects.published_doc` 列（差异 #3、#7）。

### 4.2 引用完整性校验规则（PUT 与 import 共用，失败 422 + `errors` 字段路径）

| 引用 | 目标集合 |
|---|---|
| `pages[*].components[*]`（含 group 递归）`.bindings[].variableId` | `variables[].id` |
| `alarmRules[].variableId` | `variables[].id` |
| `variables[].datasourceId` | `datasources[].id` |

### 4.3 运行态资源级联清理矩阵

| 触发事件 | 在线 WS 连接 | 采集任务 | 内存变量池 | 未恢复报警记录 | share_links |
|---|---|---|---|---|---|
| DELETE 工程 | 全部（预览+分享）收 `error(PROJECT_REMOVED)` + close 4000 | 停止 | 释放 | 随表级联删除 | 级联删除 |
| 撤销 share token | 该 token 连接 `error(SHARE_REVOKED)` + close 4000 | 不变 | 不变 | 不变 | `revoked_at=now` |
| refresh 分享链接 | 该 token 连接广播 `reload` | 不变 | 不变 | 不变 | `doc_snapshot` 更新为最新脱敏快照 |
| PUT 保存 | 连接保持，不重发 snapshot | 差量热重建 | 变量集更新 | 规则集热更新 | 不变（已建快照不跟随，需 refresh 才更新） |
| 服务重启 | 客户端退避重连 → snapshot 恢复 | lifespan 重建 | 重建 | 遗留 active 置 recovered | 不变 |
