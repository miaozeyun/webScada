# P0 分阶段任务拆解（专项深化文档 · 定稿）

依据骨架方案 mvp-first 细化，并落实评审移植项与共同缺陷修正。全文为开发计划，不含实现代码。总原则沿用骨架：每阶段结束 `docker compose up -d` 后即可演示，不做“全部完成才可跑”的大爆炸集成。

本版为最终定稿（第三轮重建）：以第一轮深化版的完整章节结构为骨架，凡第二轮统稿版已有内容以其为准；全文口径已统一按裁决表 G1~G33 执行，并逐条落实专项修复清单 (a)~(f)。相对前两版的主要口径修正：接口前缀统一 `/api/v1`（运行态 WS 端点 `/api/v1/ws/runtime`，G1）；乐观锁字段统一 `baseRevision`/`revision`（G2）；绑定映射统一 `mapping`（G4）；变量字段统一 `key/label`（G25）、换算字段统一 `scale/offset/precision`（含 `bitIndex`，G3）；心跳统一 20s ping / 2 次无 pong 判死 / 客户端 30s 判线（G18）；浏览器基线统一 Chrome/Edge ≥ 90、es2020、不用 structuredClone（G22）；表结构以 G10 权威版为准（无 `role`/`page_id`/`published_doc` 列）；报警清理任务统一为“启动执行一次 + 每 24h 间隔”（修复 c）；P0 多页仅手动页签切换、无自动轮播（G30）。

## 一、与骨架的差异（评审修正落点）

| # | 差异/补充内容 | 原因（对应评审项） |
|---|---|---|
| C1 | **换算上移到变量级**：数值换算字段 `scale/offset/precision`（含 `bitIndex` 位提取）定义在 `VariableDef`（变量级，G3），由服务端在值入 hub 前统一求值为工程值；**Binding 无任何数值换算字段**，仅保留表现层映射 `mapping`（G4：`{kind:'enum', map}` 或 `{kind:'range', bands}`）。**报警阈值一律按换算后的工程值配置与判定**，规则配置 UI 显示变量单位并注明口径 | 评审共同缺陷“告警判定基准值语义未定义”；移植亮点 4。消除“显示 72.5 却按 725 判阈值”的口径分叉 |
| C2 | **发布采用快照（G5）**：`share_links` 表含 `doc_snapshot JSONB` 列，创建分享链接时冻结一份**凭证脱敏后**的 doc；`GET /api/v1/share/{token}` 只读返回快照。编辑不直透已分享大屏；“重新发布”= 创建/刷新分享链接；**无 publish 状态机、无 published_doc** | 移植亮点 3（降级移植） |
| C3 | **凭证脱敏（G6）**：凭证 Fernet 加密存库；出口脱敏口径统一为——`mqtt.config.password` 置空、`headers` 敏感键置空、`username` **不脱敏**；凭证 PUT 合并规则：缺省/空串=保留、null=清除；导入凭证视为空，变量字典页提示补填 | 移植亮点 1 |
| C4 | **新增接口**：`GET /api/v1/health`（存活检查，供 compose healthcheck）、`PUT /api/v1/auth/password`（管理员改密，body `{oldPassword,newPassword}`，G24）、`POST /api/v1/datasources/test`（数据源连通性测试，body 即数据源配置，超时 5s，出参 `{ok,type,latencyMs,message}`，G23）、`GET /api/v1/projects/{id}/variables/values`（值快照调试接口，编辑器调试用，G28） | 评审共同缺陷：健康检查缺失、无改密路径、无连通性测试 |
| C5 | **引用完整性双路径（G12）**：保存/导入时校验 `variableId/datasourceId` 存在性，失败统一 422 并以 `{code,message,errors:[{path,message}]}` 列出字段路径（G20）；编辑器内删除变量/数据源采用“阻断展示引用清单 + 确认后一并删除关联绑定与报警规则”策略（G12），服务端 PUT 兜底 422 | 评审共同缺陷 3（编辑态删除级联缺失） |
| C6 | **运行态级联热清理（G17）**：删除工程/停用分享 token 时，对应活动 WebSocket 先推 `{"type":"error"}` 帧（code=`PROJECT_REMOVED`/`SHARE_REVOKED`）再以 close 4000 关闭，采集任务停止，hub 变量池清理 | 评审缺陷“运行态资源级联热清理缺失” |
| C7 | **公开面防护（G16）**：单 share token 并发 WS ≤ 20（`SHARE_MAX_WS_PER_TOKEN`）+ 同用户同工程 JWT 运行态 WS ≤ 10（`JWT_WS_MAX_PER_USER_PROJECT`）+ 建连 ≤ 30 次/分（`RATE_LIMIT_CONNECT_PER_MIN`）；WS 场景超限经 accept 后 `error` 帧 `RATE_LIMITED` 拒绝（G17） | 评审缺陷“公开面滥用防护缺失” |
| C8 | **报警防风暴**：同一规则前端声音节流 `soundThrottleSec`（默认 60s，G14）；活动报警广播上限 200 条（critical > warn > info 优先保留，超出带 `truncated` 标记，G15）；server 启动时遗留 `active` 报警记录统一收口为 `recovered`（G15） | 移植亮点 6 |
| C9 | **alarm_records 保留策略（修复 c 后口径）**：清理任务在 **server 启动时执行一次、之后每 24h 间隔执行**（不做固定时刻调度），删除 `recovered_at` 早于保留期（默认 30 天，`ALARM_RETENTION_DAYS` 可配）的记录，并维持单工程 200000 行上限（`ALARM_MAX_ROWS_PER_PROJECT`，超限删最旧，G15） | 评审缺陷“报警记录无限增长” |
| C10 | **补充边界声明**：数据载荷仅支持 UTF-8 JSON（CSV/十六进制/二进制不支持，写入文档）；浏览器兼容基线 Chrome/Edge ≥ 90、构建目标 es2020、不使用 structuredClone（G22）；nginx 对 `/api/v1/ws/runtime` 访问日志剥离查询串（token 脱敏）；时间戳默认采用服务器接收时间（数据源级可选 `tsPath`；载荷时间戳与服务器偏差 > ±5min，**双向、含未来时间**，视为不可信，回退服务器时间并记 warn，G26）；MQTT 默认 QoS0 + clean session，QoS1 可选并文档声明离线消息回放风险 | 评审缺陷 4/5/6 与 MQTT 语义项 |
| C11 | **报警变色优先级契约（G11）**：组件属性合成顺序为 静态 props < 绑定映射（`mapping`，G4）< 报警态（覆盖填充色 + 闪烁，恢复后回落）；**visible 绑定优先于报警**；唯一实现点 `WidgetHost.vue`，写入组件协议文档 | 评审缺陷 1（双变色链路歧义） |
| C12 | **阶段拆分调整**：骨架 M2 组件库拆为 M2a/M2b/M2c 三段（协议冻结单列）；骨架 M4 中的“分享链接 + iframe”移至 M6（G29：分享/iframe 属 M6）；M6 同时并入整体打磨 | 本任务方向建议；估算相应微调 |

### 本轮定稿修订（R1~R6，审查问题修复落点）

| # | 修订内容 | 修复的审查问题 | 落点 |
|---|---|---|---|
| R1 | **补充 WS 应用层保活帧（G18）**：server 每 20s 下发 `{"type":"ping"}`，客户端回 `{"type":"pong"}`；服务端连续 2 个周期（约 40s）未收到 pong 判定死连接并关闭；客户端 30s 无任何入站帧（含 ping）即判线重连，指数退避 1s 起、上限 30s，致命 code 停止重连。ping 与业务帧同等计入“最近收帧时间”（浏览器 WS API 无法观测协议层 ping/pong，客户端判活必须基于应用层帧）。nginx 反代显式配置 `proxy_read_timeout 75s` / `proxy_send_timeout 75s`（下限 = 判死周期 40s = 20s × 2，取 75s 留裕量），摆脱对默认 60s 的依赖 | WS 保活缺失，与判线自相矛盾；静默大屏周期性误重连 + snapshot 重发风暴 | M0 nginx、M4 `ws.ts`/`ws_manager`、M6 WS 协议文档 |
| R2 | **放弃 composite-only 假承诺**：明确 `stroke-dashoffset` 为 paint 类动画（非合成器属性，Chrome/Edge 每帧触发 paint）；M2c 流动动画验收改为“无 layout 抖动、paint 频率与面积可控”；实现保持 `stroke-dashoffset` + CSS animation，禁触发 layout 的属性 | M2c 验收在现有浏览器不可达成；风险对策把 stroke-dashoffset 误归类为合成属性 | M2c 目标/交付物/验收/风险表 |
| R3 | **删除“整体容器一次光栅化”表述**（不可操作）。可执行策略：ECharts 适配器（落点 M2b）在容器 `transform: scale` 变化时按 `scale × devicePixelRatio` 重建画布物理分辨率（re-setOption/resize）；文本类组件维持 DOM 渲染由浏览器重栅格化；M2b/M4 各增对应验收条目 | scale 下模糊对策不可操作；M4 抽查 0.75/1.25 无落点 | M2b 交付物/验收、M4 风险表/验收 |
| R4 | **更正“Loguru 限频”为自研小件**：基于 Loguru `filter` 或自建包装器实现“同源同级别 60s 一条”（Loguru 无内置限频/去重参数，非开箱即用） | 给库安上它没有的能力 | M3 交付物/验收 |
| R5 | **工程 JSON 导出/导入端点显式落在 M0（G7/G29）**：`GET /api/v1/projects/{id}/export`（JSON body，前端 Blob 下载，复用 C3/G6 脱敏）、`POST /api/v1/projects/import`；**导出/导入端点 M0 交付，round-trip 契约测试在 M6 交付（G29）** | 导出功能无交付阶段、无验收条目、M0/M6 指向模糊 | M0 交付物/验收、第四节 |
| R6 | **M3 ws 源联调目标改为 compose 内置回显服务** `echo-ws`（仓库自带 `tools/echo-ws/`，基于 Python `websockets` 库的纯回显实现，`--profile dev` 启动，默认 profile 不加载、生产零负担）；公网 echo 降为可选附加验证 | 依赖外部公网服务，验收不可重复 | M3 交付物/验收 |

其余架构、技术栈（前端 Vue3+TS+Vite+Pinia+Element Plus+ECharts+SVG 图元+原生 WS；后端 FastAPI+PostgreSQL+异步 SQLAlchemy 2.0+Pydantic v2+Uvicorn+Loguru+EMQX）、目录结构、量化规模上限（2C4G、≤50 连接、≤5000 变量、单页 ≤200 组件、保存防抖 3s、doc 体积 ≤1MB 正常 / 1~2MB 前端 UI 告警 / >2MB 服务端 422 `doc_too_large`，G21）均沿用骨架；WS 帧协议按 G19 执行：`snapshot`（内嵌 `activeAlarms`）/ `values` / `alarm` / `alarmClear` / `reload` / `ping` / `pong` / `error`，P0 无 subscribe 帧（连接即全工程订阅），`subPages` 为 P2 预留。

## 三、各阶段详述

### M0 基础设施与工程骨架

**目标**：四容器一键起，账号与工程 CRUD 闭环，为全部后续阶段提供可运行底座，并把安全与运维基线（脱敏、日志、healthcheck、保留策略参数）一次性铺好。

**前置依赖**：无。

**交付物**
- 仓库骨架：`server/`、`web/`、`deploy/nginx/nginx.conf`、`docker-compose.yml`、`.env.example`。
- docker-compose 四服务：nginx / server / postgres / emqx，含 healthcheck（server 探 `/api/v1/health`），`restart: always`。
- FastAPI 骨架：异步 SQLAlchemy 2.0 + Pydantic v2、Loguru、pydantic-settings、alembic 初始迁移（`users`、`projects`、`share_links`——**含 `doc_snapshot` 列**、`alarm_records`）。**表结构以 G10 权威版为准**：`users(id,username,password_hash,created_at)`、`projects(id,name,description,doc JSONB,revision,owner_id,created_at,updated_at)`、`share_links(id,project_id,token,doc_snapshot,expires_at,revoked_at,last_access_at,created_at)`、`alarm_records(id,project_id,rule_id,variable_key,value,level,message,status,triggered_at,recovered_at)`；**无 `role`/`mock_enabled`/`published_doc` 列，`share_links` 无 `page_id`**（G10）；DB 主键一律为服务端 UUID（G9）。
- 管理员初始化脚本（按 `.env` 的 `ADMIN_USER/ADMIN_PASSWORD`，bcrypt 落库，无注册接口）。
- 接口：`POST /api/v1/auth/login`、`POST /api/v1/auth/logout`（进程内 jti 黑名单）、`GET /api/v1/auth/me`、`PUT /api/v1/auth/password`（校验旧密码，body `{oldPassword,newPassword}`，G24；返回 204，旧 token 至自然过期 2h，不做全局作废，文档声明——接口语义以《03-接口清单》为准）、`GET /api/v1/health`。
- 项目 CRUD；**创建项目不携带 doc（G7）**；导入/导出走独立端点：`POST /api/v1/projects/import`、`GET /api/v1/projects/{id}/export`（JSON body，前端 Blob 下载，G7）。导入处理链：服务端**仅校验 `schemaVersion`**（不支持版本 422 `version_unsupported`；版本迁移唯一实现点在前端 `migrateDoc()`，G8）→ Pydantic v2 结构校验 → **引用完整性校验**（422，错误体统一 `{code,message,errors:[{path,message}]}`，G20，message 含具体路径如 `pages[0].components[2].bindings[0].variableId`）；PUT 带 `baseRevision` 乐观锁（409 `REVISION_CONFLICT`，G2）；doc 体积 >2MB 拒绝 422 `doc_too_large`（G21）；doc 内部对象 id 为前端 nanoid（导入保留），`doc.project.id` 与 DB UUID 对齐（导入时重新生成，G9）；doc 内部 id 前缀建议值 `page_/cmp_/var_/ds_/bnd_/alm_`（仅建议、非校验），`project.name ≤ 128` 字符（G33）。
- 前端骨架：Vue3 + Vite + TS + Router + Pinia + Element Plus + axios（JWT 拦截器、401 跳登录、409 冲突提示组件；构建目标 es2020，不使用 structuredClone，G22）、登录页、项目列表页（新建/删除/导入 .json/**导出 .json**：调 `GET /api/v1/projects/{id}/export` → 复用 C3/G6 脱敏工具置空 `mqtt.config.password` 与 `headers` 敏感键（`username` 不脱敏）→ 触发浏览器 Blob 下载）。**导出/导入端点 M0 交付，round-trip 契约测试在 M6 交付（G29/R5）**；该脱敏实现与 M6 round-trip 测试共用同一契约。
- nginx：`/api/v1` 反代 + WebSocket Upgrade 配置（运行态端点 `/api/v1/ws/runtime`，G1）+ **`proxy_read_timeout 75s` / `proxy_send_timeout 75s`（下限 ≥ 心跳判死周期 40s = 20s × 2，防止默认 60s 切断空闲连接，G18/R1）**；`/s/` 路径 `frame-ancestors` 策略占位；**`/api/v1/ws/runtime` 访问日志剥离查询串**（map + log_format）。
- 部署文档初版（含 `.env` 各项说明：`ALARM_RETENTION_DAYS`、`ALARM_MAX_ROWS_PER_PROJECT`（G15）、`SHARE_MAX_WS_PER_TOKEN`、`JWT_WS_MAX_PER_USER_PROJECT`、`RATE_LIMIT_CONNECT_PER_MIN`（G16）等参数）。

**验收标准**
- [ ] 干净机器 `docker compose up -d` 一次通过，四容器 healthy，`curl /api/v1/health` 返回 200。
- [ ] `.env` 配置的管理员可登录，错误密码 401，错误响应统一 `{"code","message"}`（校验失败统一 422 + G20 错误体）。
- [ ] 建工程（不携带 doc）→ 列表（不含 doc）→ 详情（含 doc）→ 删除（204，级联 share_links/alarm_records）全通；`doc.project.id` 与 DB UUID 一致（G9）。
- [ ] 导入含非法 `variableId` 引用的 doc 返回 422，错误体 `errors` 数组指出具体字段路径（G20）。
- [ ] 导入含不支持的高 `schemaVersion` doc 返回 422 `version_unsupported`（G8）。
- [ ] 导出 .json（R5/G7）：文件中 `mqtt.config.password` 与 `headers` 敏感键为空、`username` 保留（G6），且该文件可直接再次导入成功（导入凭证视为空，G6）。
- [ ] 保存 doc 超过 2MB 返回 422 `doc_too_large`（G21）。
- [ ] 两浏览器同时保存同一工程，后者得 409 `REVISION_CONFLICT`（G2）且前端有明确提示。
- [ ] 改密（G24）：旧密码校验失败按统一校验口径返回 422（G20）；改密成功返回新 token 并可登录。
- [ ] nginx access log 中 grep 不到明文 JWT/share token。
- [ ] 前端登录 → 建工程 → 列表 → 删除页面流程可操作。

**主要风险与对策**

| 风险 | 对策 |
|---|---|
| Windows/Linux 卷权限、换行符差异导致 compose 启动失败 | 仓库统一 LF（.gitattributes），命名卷，文档写明 Docker Desktop 最低版本 |
| server 启动时 alembic upgrade 与 postgres 就绪时序 | compose `depends_on: condition: service_healthy` + 入口脚本重试 |
| doc 校验过严导致合法导入被拒 | Pydantic 模型 `extra='ignore'`，仅校验已知契约，未知字段容忍 |

### M1 画布编辑器核心

**目标**：自由布局画布全能力，能搭出静态画面并稳定保存/重开；产出右侧属性面板框架供 M2a/M3 复用。

**前置依赖**：M0。

**交付物**
- `CanvasStage`：pointer 拖拽、8 向缩放柄、旋转（角度入 `rotate`）。
- 吸附与对齐参考线：阈值 5 设计像素（组件边缘/中心、画布中线）。
- 图层面板：显隐/锁定/z 序调整，与画布双向同步。
- 框选、成组/解组（`group` 节点递归 `children`，组内相对坐标）。
- `history.ts`：undo/redo，页面级 JSON 快照（深拷贝用 JSON 序列化实现，**不使用 structuredClone，G22**），提交式入栈（松手/防抖合并后才入栈），上限 50 步淘汰最旧。
- 属性面板框架：按 registry 的 `propsSchema` 渲染表单（本期以 text/image 的 schema 验证）。
- 画布缩放（Ctrl+滚轮，25%~400%）与平移（空格拖移）。
- 页面管理：增/删/改名/排序（`Page.order`）；doc 对象 id 按建议前缀生成（`page_`/`cmp_`，G33，仅建议非校验）。
- 保存链路：3s 防抖 + `baseRevision` 乐观锁（G2）+ 409 冲突提示 + 断网失败不丢内存态。

**验收标准**
- [ ] 拖入组件自由定位，缩放/旋转可用；保存 → 刷新 → 重开，坐标/尺寸/角度/图层完全一致。
- [ ] 距其他组件边缘或画布中线 ≤5px 出现吸附线并吸附。
- [ ] 图层显隐/锁定/排序即时生效并正确写入 `visible/locked/z`。
- [ ] 框选两组件成组后整体拖动，组内相对坐标正确；解组还原。
- [ ] 一次拖拽全程仅产生 1 条 undo 记录；Ctrl+Z / Ctrl+Shift+Z 正确；超 50 步淘汰最旧。
- [ ] Ctrl+滚轮缩放流畅，缩放不改变导出 doc 坐标。
- [ ] 断网保存失败有提示，本地编辑态不丢失。
- [ ] 双开编辑保存，后者 409 `REVISION_CONFLICT` 并提示刷新。

**主要风险与对策**

| 风险 | 对策 |
|---|---|
| 旋转 + 缩放柄同时操作的几何数学复杂 | P0 交互约定：旋转后缩放柄按轴对齐包围盒工作，边界行为写入文档（已知限制，不做斜向缩放数学） |
| undo 快照内存膨胀 | 只压当前页快照、50 步上限、属性连改防抖合并 |
| 吸附计算量大 | 仅与视口内可见组件比较，参考线 DOM 复用 |

### M3 变量字典与四类数据接入

**目标**：后端数据通路全通（四源 → hub → 值快照），变量级换算（G3）落位，数据源可配置期验证，删除级联策略实现。

**前置依赖**：M0（强）；绑定编辑器 UI 子项依赖 M1 属性面板框架（可后移至本阶段末段或 M4 初，不阻塞后端线）。

**交付物**
- 变量字典 UI：变量增删改（**key**（全局唯一标识，G25）/**label**（显示名，G25；废弃旧字段 `name`）/type/unit/datasourceId/address/jsonPath/**scale/offset/precision/bitIndex**（G3，含位提取）/MockSpec/description；变量 id 建议前缀 `var_`，G33）。
- **删除级联（G12/C5）**：删除变量/数据源前扫描引用（bindings + alarmRules），弹窗列出引用清单（组件名/属性路径/规则名）；默认阻断；确认后**关联绑定与报警规则一并删除**（G12），undo 可整体恢复；服务端 PUT 兜底校验 422（G12/G20）。
- collector 四源（按 mock → mqtt → rest → ws 顺序接入）：
  - `mock_source`：sine/ramp/random/square 四种 MockSpec；**Mock 为数据源类型之一，enabled 即总开关，无独立 mock 接口/表列（G13）**；
  - `mqtt_source`：aiomqtt，**默认 QoS0 + clean session**，QoS1 可选（文档声明离线回放可能造成值跳变，由用户自担）；断线指数退避重连；payload 非 JSON → `q='bad'` + 自研限频日志（R4 小件，同源同级别 60s 一条）；凭证 Fernet 加密存库（G6）；
  - `rest_source`：httpx.AsyncClient 定时轮询，单源任务防堆积（上一轮未完成则跳过本 tick）；`headers` 敏感键脱敏出口置空、`username` 不脱敏（G6）；
  - `ws_source`：上游长连接客户端，重连 + 心跳；联调目标为 compose 内置回显服务 `echo-ws`（**R6**：仓库自带 `tools/echo-ws/`，基于 Python `websockets` 库的纯回显实现，`--profile dev` 启动；默认 profile 不加载，生产部署零负担）。
- `hub`：进程内 Pub/Sub（per-project），**接口抽象预留 Redis 替换；输出侧预留 `ValueSink` 协议位**（P1 历史回放挂点，本期仅 ws_manager 与 rules_engine 两个实现）。
- **服务端换算（G3）**：入 hub 前一次换算为工程值——`bitIndex` 先做位提取，再 `v = raw * scale + offset`，按 `precision` 取位；解析失败/类型不符 → `q='bad'` 不抛异常；**自研日志限频小件（R4）**：基于 Loguru `filter` 或自建包装器实现“同源同级别 60s 一条”（Loguru 无内置限频/去重参数）。时间戳策略按 G26：默认服务器接收时间；数据源级可选 `tsPath`，载荷时间戳与服务器偏差 > ±5min（双向、含未来时间）视为不可信，回退服务器时间并记 warn。
- 工程保存热更新：datasource/variable/alarmRules 差量比对重建采集任务与规则集。
- `POST /api/v1/datasources/test`（G23）：body 即数据源配置；mqtt（连接+订阅验证）/ rest（单次请求）/ ws（建连+首帧）/ mock（恒成功），超时 **5s**，出参 `{ok, type, latencyMs, message}`。
- `GET /api/v1/projects/{id}/variables/values`（G28）：当前值快照（Bearer），供变量字典调试面板（编辑器调试用）。
- 导入脱敏工程（凭证视为空，G6）后，变量字典页提示补填凭证（C3）。

**验收标准**
- [ ] mock 源：4 种 MockSpec 变量按各自节奏跳动，调试面板可见；数据源 `enabled=false` 时整体停采（G13）。

### M4 绑定求值与运行态渲染

**目标**：编辑的画面跑起来：原生 WebSocket 推送 → binder 求值 → 组件数值/颜色/显隐联动；多页（手动页签）、五种自适应、全屏、编辑器预览。

**前置依赖**：M1 + M2a + M3（M2b/M2c 完成度越高演示越全，最低仅需基础类组件联调）。

**交付物**
- `runtime/ws.ts`：原生 WebSocket，端点 `/api/v1/ws/runtime`（G1），token 走查询串；连接后收 `snapshot` 帧（**内嵌 `activeAlarms`**，G19/G28，本期报警列表 M5 完善）+ `values` 增量；**应用层保活（R1/G18）：server 每 20s 下发 `{"type":"ping"}`，客户端立即回 `{"type":"pong"}`——浏览器 WS API 无法收发/观测协议层 ping/pong，客户端判活必须基于应用层帧，ping 与业务帧同等刷新“最近收帧时间”**；客户端 30s 无任何入站帧（含 ping）判为断线，指数退避重连（1s 起、上限 30s），重连后以服务端重发的 `snapshot` 直接覆盖本地；收到致命错误 code（`TOKEN_EXPIRED`/`PROJECT_REMOVED`/`SHARE_REVOKED`/`SHARE_EXPIRED`）停止重连；服务端错误语义为 accept 后推 `error` 帧（code 枚举见 G17）再 close 4000；收到 `reload` 帧重新拉取快照（G17/G19）。
- server `ws_manager`（R1 补充登记）：连接鉴权、`snapshot` 首发（内嵌 `activeAlarms`）、`values` 100ms 合帧增量广播、`alarm`/`alarmClear` 即时帧；**每 20s 定时下发 `{"type":"ping"}`，连续 2 个周期（约 40s）未收到客户端 `pong` 判定死连接并主动关闭清理（G18）**；拒绝类场景统一 accept 后 `error` 帧 + close 4000（唯一例外 `PROJECT_MISMATCH` 保持连接，G17）。
- `runtime/binder.ts`：按 `Binding`（G4 结构 `{id, prop, variableId, mode: 'value'|'color'|'visibility', mapping?}`）求值——**数值已是工程值（服务端已换算，G3；Binding 无数值换算字段）**，前端仅求值 `mapping`（G4：enum/range 映射，离散值/区间 → 颜色/布尔显隐）与目标属性；结果写入 runtime store，组件响应式联动；渲染优先级（静态 props < 绑定映射 < 报警态、visible 绑定优先于报警）唯一实现点 `WidgetHost.vue`（G11）。
- `RuntimeView.vue`：复用 widgets 渲染器（无 SelectionLayer）；**多页切换为手动页签（P0 无自动轮播，G30，修复 a）**；**五种自适应容器**（整体 `transform: scale`：fixed / fit-width / fit-height / fit-contain（默认）/ stretch，stretch 标注“可能变形”）；全屏大屏模式（Fullscreen API）。
- 编辑器“预览”入口。
- stale/bad 值 UI 表达：组件灰显（依据 `q` 位）。
- （低成本）变量测试注入面板：**纯前端本地实现（G27）**——编辑态预览直接覆盖 runtime store，不落库、不经服务端，验证绑定联动。

**验收标准**
- [ ] 预览打开 ≤1s 收到 `snapshot`，mock 变量实时刷新到组件数值。
- [ ] `mapping: {kind:'enum', map:{"1":"#22c55e","0":"#64748b"}}`（G4）绑定 status-light 的 fill，值切换颜色即时切换。
- [ ] visible 绑定：变量为 false 时组件隐藏，恢复后显示。
- [ ] 五种自适应分别在 1366×768 / 2560×1440 / 竖屏窗口验证：fixed 出滚动条、fit-width 横向铺满、fit-contain 居中留白、stretch 铺满且 UI 有变形标注。
- [ ] 多页手动页签切换流畅（无自动轮播入口，G30），Performance 面板确认非当前页组件无更新开销。
- [ ] `docker restart server` 后前端 30s 内自动重连并重新 snapshot，数据无错乱（真实断连场景，与 R1 保活判线不冲突）。
- [ ] 静默大屏（变量 2 分钟无值变化）不出现周期性断线重连，连接稳定（20s 应用层 ping 保活生效，R1/G18）。
- [ ] fit-contain 下 0.75×/1.25× 容器缩放抽查：图表画布按 scale×devicePixelRatio 重渲染、图表与 DOM 文字清晰无模糊（R3）。
- [ ] 全屏进入/退出正常（含 Esc）。
- [ ] 浏览器控制台不打印含 token 的 URL 日志。

**主要风险与对策**

| 风险 | 对策 |
|---|---|
| WS token 在查询串可能进各级日志 | M0 已铺 nginx 日志脱敏；文档建议生产启用 HTTPS |

### M5 基础告警

**目标**：报警闭环：规则配置 → 服务端评估 → 落库 → 推送 → 变色 + 声音，含防风暴与保留策略。

**前置依赖**：M3 + M4。

**交付物**
- 报警规则配置 UI：variableId/op/threshold/level/message/enabled/hysteresis/durationMs/sound；**UI 显示变量单位并注明“阈值基于换算后工程值”（G3 口径）**；报警全局声音/级别设置存 `doc.settings.alarm`（字段：`soundEnabled`、`levelColors`、`soundThrottleSec` 默认 60），**随 doc PUT 保存，无独立端点（G14）**。
- `rules_engine`：op+threshold（阈值按工程值口径判定，G3）；`durationMs` 持续判定（进程内记 firstViolatedAt，重启重新计时——声明为可接受行为）；`hysteresis` 回差防抖；恢复判定；非数值输入跳过评估并计数；工程保存热更新规则集。
- `alarm_records` 落库/恢复更新（字段按 G10：`variable_key`/`status`/`triggered_at`/`recovered_at`）；**server 启动时遗留 active 记录统一收口标记 recovered（C8/G15）**；**报警清理任务在 server 启动时执行一次、之后每 24h 间隔执行（非固定时刻调度，修复 c）**：按 `ALARM_RETENTION_DAYS`（默认 30 天）删除 `recovered_at` 过期记录（C9/G15），并维持单工程 200000 行上限（`ALARM_MAX_ROWS_PER_PROJECT`，超限删最旧，G15）。
- WS 帧（G19/G15）：`alarm` / `alarmClear` 即时帧（不走合并窗口）；连接建立/重连时 `snapshot` 帧内嵌 `activeAlarms` 下发当前未恢复报警，前端列表以此恢复，不调 REST 补齐（G28）；**活动报警广播上限 200 条（critical > warn > info 优先保留，超出带 `truncated` 标记，C8/G15）**。
- 前端：报警列表（当前 active + 最近恢复，工程级全局列表，与页面无关——多页语义按全项目订阅全量推送，G19）；全局报警条按 level 变色（info 蓝 / warn 橙 / critical 红，色表对齐 `doc.settings.alarm.levelColors`，G14）+ 徽标计数。
- 声音：Web Audio；AudioContext 首次用户手势解锁提示条 + “测试声音”按钮；critical 循环提示音可手动停止；**同一规则声音节流 `soundThrottleSec`（默认 60s，C8/G14）**；静音/声音开关写入 `doc.settings.alarm.soundEnabled` 并随 doc 保存（G14，无独立端点）。
- 变色优先级落地（G11）：组件 `alarmLevel` 由关联变量的最高级别活动报警驱动，覆盖填充色并触发闪烁、恢复回落；**visible 绑定优先于报警；唯一实现点 `WidgetHost.vue`**（M2a 已入协议）。
- 级联热清理（C6/G17）：删除工程 → 该工程活动 WS 收 `error` 帧（`PROJECT_REMOVED`）后以 close 4000 关闭、采集任务停止、hub 变量池清理、未恢复报警随级联删除。

**验收标准**
- [ ] mock square 变量越限：≤1.5s 内报警帧到达、列表出现、报警条变色、（解锁后）声音响起。

- [ ] durationMs=5000：瞬时越限 3s 不触发，持续 5s 触发。
- [ ] 重启 server：遗留 active 记录被标记 recovered，`snapshot` 内嵌 `activeAlarms` 与库内一致（G19）。
- [ ] 刷新页面/断线重连后报警列表不丢（来自 `snapshot.activeAlarms`，无需额外 REST 请求，G28）。

### M6 发布/分享/联调交付与整体打磨

**目标**：一键发布语义（快照）、分享/iframe、示例工程、性能与安全验收、文档齐套、打包发布。

**前置依赖**：M0~M5。

**交付物**
- 分享链接（C2/C3/G5）：
  - 管理端 `POST /api/v1/projects/{id}/shares`（创建）：生成 token，冻结**凭证脱敏后**的 doc 快照至 `share_links.doc_snapshot`；`POST /api/v1/shares/{token}/refresh` = “重新发布”（刷新快照）；`DELETE /api/v1/shares/{token}` = 停用（管理面复数/公开面单数为有意设计，接口文档声明）；
  - 公开端 `GET /api/v1/share/{token}`：无鉴权只读返回快照；**分享页报警不设公开 REST**，运行态经 WS 连接时 `snapshot` 帧内嵌 `activeAlarms` + 后续 `alarm`/`alarmClear` 帧下发（G28）；

- 级联热清理全链路收口（C6/G17）：删除工程/停用 token → WS 收 `error` 帧（`PROJECT_REMOVED`/`SHARE_REVOKED`）后关闭、采集停止、内存清理，集成测试覆盖。

- 文档齐套：部署手册（含 30 分钟部署路径）、使用手册（**含运行口径披露：变量删除/改名/换绑保存后，引擎按最新 doc 运行，已分享快照中旧变量无值流、对应组件显示空/停滞，刷新快照（重新发布）即恢复——属预期行为，G32**）、组件协议、**WS 协议（R1/G17/G18/G28：帧清单含 snapshot（内嵌 activeAlarms）/ values / alarm / alarmClear / error（code 枚举 `TOKEN_EXPIRED`/`PROJECT_REMOVED`/`SHARE_REVOKED`/`SHARE_EXPIRED`/`RATE_LIMITED`/`PROJECT_MISMATCH`（不关闭）/`INTERNAL_ERROR`，close code 统一 4000）/ reload（快照刷新通知，客户端重拉 doc）/ ping / pong，预留 subPages；保活语义：server 20s 应用层 ping（连续 2 次共 40s 无 pong 判死）、客户端回 pong、客户端 30s 无入站帧判线重连（致命 code 停止重连，网络级失败指数退避 1s 起上限 30s）、nginx 超时 ≥ 40s 判死周期）**、**边界声明**（仅 JSON 载荷、只读监控无控制写入、不做历史库/3D/视频、单 worker、浏览器基线 Chrome/Edge ≥ 90（G22）、规模上限、doc 体积阈值（G21）、MQTT QoS 语义、时间戳策略）。
