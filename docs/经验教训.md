## E2E / 测试

### [2026-10-22] 外发 webhook 类验收：先查渠道 URL 约束与节流语义
- **现象**：写 `doc.settings.notify` 的本地 http 接收器被 422 拒；监听脚本又因 notify 节流（缺省 300s/规则）误判链路失败。
- **根因**：渠道 URL 强制 `^https://`（防明文出口泄漏 secret 的刻意约束）；断言未计入节流窗。
- **解决/预防**：接收器侧 TLS（自签 CA 注入容器 certifi）；断言锚「渠道生效之后触发的报警」（status 仅 `triggered/acked/cleared`）；外发验收先查 URL 约束，时序断言留节流窗余量。

### [2026-10-20/28] 浏览器 E2E 三坑 + 联调上游陷阱
- URL 断言一律精确前缀（`http://…/editor/`），`**` 通配不可靠。
- Element Plus 受控输入 `fill()` 无效：`pressSequentially`/`type` 键盘注入，写后 blur 触发校验。
- UI 登录受 IP 限流（10 次/分），连跑 E2E 会 429 且表现为「登录没反应」：复用 `storageState`，或 `RATE_LIMIT_ENABLED=false`。
- 宿主机仿真上游（scripts/sim/*）：server 在容器内 → `ws://host.docker.internal:8765`（裸跑才用 `127.0.0.1`）；脚本依赖 server venv 的 `websockets`；`WS_FEED_HOST=0.0.0.0` 才对容器可达；浏览器看到的 `/api/v1/ws/runtime` 与该脚本无关。

### [2026-10-20/27] 单测隔离四课（pytest + Pinia）
- 每测试一个事件循环：引擎/全局连接必须每测试重建（conftest 已做）；env 必须在 import app 之前设置；`from tests.conftest import` 依赖 `pythonpath=["."]`。
- Pinia 单例：store 单测逻辑正确却断言失败——模块级 history 单例带着上一用例的条目，`setActivePinia` 只重置 store state 不重置模块级闭包。单例显式导出、受影响 spec 的 beforeEach 显式重置；「状态在 Pinia 外」的单例（history/音频/WS 句柄）一律列入隔离清单。
- notify 打桩：报警/规则测试随机 `InvalidRequestError`——notify 派生任务并发读库走模块级 SessionLocal 跨事件循环。不测外发链路的文件 autouse 打桩 `notify.send_alarm`；新服务提供 session_factory 测试缝。
- JSON 列标脏：测试直改 JSON 列后 `p.doc = dict(p.doc)` 不落库（flush 按值相等判净变更）→ `flag_modified` 显式标脏。

## 前端

### [2026-10-28] crypto.randomUUID / clipboard 只在安全上下文可用：内网 http://IP 全不可用
- **现象**：`localhost` 点「演示案例 → 生成」正常；部署后经 `http://<服务器IP>:8088` 点同一按钮**完全无反应**——无 toast、无 console、无请求。
- **根因**：`demos/shared.ts`、`stressDoc.ts` 用 `crypto.randomUUID()`，该 API 只在安全上下文（HTTPS/localhost）存在，明文 HTTP 下为 `undefined`，调用即 `TypeError`；调用方空 `catch {}`（注释称「由拦截器弹 422」）把它全吞掉——本地同步异常根本到不了 axios 拦截器。实测 `http://<服务器IP>:8088` → `isSecureContext=false`，`randomUUID`/`clipboard` 均 `undefined`。
- **解决**：新增 `utils/uuid.ts` 的 `uuidV4()`（`crypto.getRandomValues`，保留 v4 变体位）替换两处；`ShareDialog` 的 `navigator.clipboard` 补 `execCommand('copy')` 兜底；演示/压测生成的 `catch` 改「非 axios 错误且未 handled 才弹窗」。
- **预防**：`crypto.randomUUID/subtle`、`navigator.clipboard`、`serviceWorker`、`getUserMedia`、`Notification` 都要问「局域网 HTTP 下还存在吗」——交付形态是内网 `http://IP`，这类 API 等于不可用。空 `catch {}` + 「拦截器会提示」的注释是最坏组合。验收必须在**局域网 IP** 入口跑一遍，localhost 永远测不出。

### [2026-10-21/28] 台账缩略图五因：静默失败、保存竞态、缩放态成像、截图占保存链路、手势打断
- **现象**：① 所有卡片永远「保存后自动生成」，doc 里没有 thumbnail 且无报错；② 生成出来的缩略图是「左上角小图 + 大片空白」。
- **根因**：① TitleBar 的 `color-mix()` 让 html2canvas 整页截图抛错，catch 静默；② 手动保存「先截图后 PUT」期间，3s 防抖自动保存先把无缩略图 doc 落库并清 dirty，随后 save() 因 `!dirty` 直接返回；③ html2canvas 按元素**实际呈现**成像——沿用「适应画布」缩放就只截到左上角；④ 截图（整页 1:1 重排 + 光栅化）跑在保存链路上堵主线程数百 ms（「点保存卡一下」），首次还要现场下载 chunk；⑤ 拖拽中截图会改 transform，打断坐标换算。
- **解决**：渐变改固定 rgba，catch 留 `console.warn`。缩略图彻底脱离保存链路：`refreshThumbnail()` 走 `requestIdleCallback`（timeout 2s 兜底）+ 60s 节流 + 在途去重，截完 `setThumbnail` 标脏由防抖保存带回；`captureThumbnail` 用 html2canvas 的 `onclone` **只在克隆体里**把 `.canvas-stage` 的 transform 归零并钉到 (0,0)，裁剪切设计尺寸——真画布一动不动，既不闪也不打断拖拽（早期版本靠临时 `thumbCapture` 改真实 transform，虽然能出图但纯属自找麻烦）；`ignoreElements` 跳过画布外的 SVG（组件库 75 张图元缩略卡等 500+ 个），单次截图从 2.4s 压到 ~250ms；手势中跳过；`preloadThumbnail()` 空闲预取 html2canvas；离开编辑器 `wait` 等落库；导出/分享快照脱敏且剥掉 thumbnail，不必截。
- **预防**：保存链路禁止重活（重排/光栅化/动态 import）；渲染库按「实际呈现」成像——先问「它截的是 DOM 还是克隆体」，能改克隆体（`onclone`）就别动真实 DOM；静默 catch 一律留日志；验证方法是拦截 `PUT /projects/*` 看 body 里有没有 `thumbnail`，并把 dataURL 解出来看**画面是否铺满 320×180**，只看「有没有图」会漏掉「小图 + 空白」。

### [2026-10-28] 台账卡片：auto-fill 末行空洞 + minmax 固定上界反被当列宽算
- **现象**：只有 3 个工程时卡片挤左、右侧空整列；默认进表格视图，缩略图入口被埋。
- **根因**：`repeat(auto-fill, minmax(230px, 1fr))` 按容器宽度切列，末行不满仍保留空轨道；换成 `minmax(230px, 460px)` + auto-fit 想封顶，Chrome 反按**上界**算轨道数（20 项只排 2 列）；默认视图常量写死 `'table'`。
- **解决/预防**：卡片区改 `flex-wrap` + `.project-card{flex:1 1 230px; max-width:460px}`，默认视图改卡片（切表格后仍按 localStorage 持久化）；项数不定别用 auto-fill 排最小宽度，`minmax()` 固定上界先量一格再定稿；改默认值连带 grep 依赖它的测试夹具（e2e 全走 `.el-table` 断言，`login()` 已显式切回表格）。

### [2026-10-21] 性能红线：常驻渲染与交互热路径
- **常驻大屏**：分享页静置 2 分钟 Layout 60 次/秒（SMIL 液面动画），JS 堆稳定但一体机发热卡顿 → 禁用 SMIL、SVG 子元素动画、`background-position` 动画（都不走合成层）；管道流动用扩展伪元素 translateX + overflow 裁剪；AudioContext 卸载即 close（上限约 6）；ack id/历史缓冲封顶。验收用 CDP `Performance.getMetrics` 长跑看 layouts/nodes，别只看内存。
- **编辑交互四源**：逐事件写 doc + 重算吸附 → rAF 合帧（抬起前 flush 末帧）；move 里 `getBoundingClientRect()` → 手势期缓存视口 rect；自动保存整页截图 → 节流并移出保存链路；`backdrop-filter` 每帧重算 → 去掉。
- **预防**：交互热路径禁止逐事件布局读取与全量序列化；「保存后副作用」一律节流或移出主线程。

### [2026-10-27] 坐标系口径必须写进签名：组内粘贴偏移 + Ctrl+V 不跟鼠标

### [2026-10-27] 选中框必须跟随节点自身旋转：「已知限制」= 用户眼里的重叠 bug
- **现象**：旋转过的组件一选中，斜置内容 + 轴对齐旧框（带柄带 W×H 徽标）同屏叠加，被报「旋转重叠」；doc 数据干净，纯渲染层假象。

### [2026-10-29] 官网首屏视频偶发停在静态海报（“数据不动”）
- **现象**：官网首屏置顶案例明明录的是真实运行画面，用户反馈「数据不动」，刷新后才恢复；现场只能看到缓慢推近的静态海报。
- **根因一（前端）**：`showcase.js` 的 `revealOnFirstFrame()` 只凭「抽帧平均亮度 > 232 判白」决定是否淡入视频，且探测失败时 12s 后**放弃淡入**（视频仍在后台播）。部分解码路径下 `drawImage(video)` 恒返回白帧，于是永远停在海报；另在弱网/首帧慢时也会长时间只有海报。
- **解决一**：加时间兜底——`!video.paused && readyState >= 2 && currentTime > 0.3` 且已等 2.2s 就显示（海报始终垫底，不会白屏）；抽帧判白仅用于「提前」显示，不再作为唯一放行条件。
- **根因二（部署，2026-10-29 追加）**：公网访问时浏览器**一个字节都拿不到**视频——`HEAD` 200/206 正常、`GET`（哪怕 `Range: bytes=0-0`）挂死 90s 返回 0 字节。同一份 2,193,624 字节文件在服务器上复制成 `_probe.bin`(octet-stream) / `_probe.jpg`(jpeg) 秒回，复制成 `_probe.webm`(video/webm) / `_probe.mp4` / `_probe.m4v` 全挂；把同一 URL 的 MIME 改成 octet-stream 后立刻 200/0.37s。**链路中间有设备按 `Content-Type: video/*` 卡死响应**（服务器本机 curl 公网 IP 的 hairpin 回环正常，故不在 nginx/容器/文件侧）。
- **解决二**：`deploy/website/nginx.conf` 与 `deploy/nginx/templates/site.conf.template` 各加一条 `location ~* \.(webm|mp4|m4v)$ { types { } default_type application/octet-stream; }`，且必须排在 `.css|.js|…` 资源正则**之前**（nginx 正则 location 命中即停）。浏览器对 `<video>` 按内容嗅探解码，实测 octet-stream 下 `readyState 4 / videoWidth 1920 / currentTime` 正常推进。
- **预防**：媒体/画布探测类判据必须有「探测失效时的上限时间」，不能出现「永远等不到就什么都不做」的分支；「画面不动」类问题先看视频元素 `paused/currentTime/opacity` 三项，再看内容。**判定「前端 bug 还是传不动」用二分法**：同一 URL 换个 MIME/换个扩展名各取一次，再加一次服务器本机 hairpin 对照——三者一分就能定位到是链路、是 MIME、还是前端。不要用「文件大/网络慢」解释 `HEAD` 正常而 `GET` 零字节的现象。

### [2026-10-29] radial-gradient 的 `<size>` 是半径不是直径
- **现象**：给首屏视频加「淡淡光晕」，按 `ellipse 120% 112%` 写边缘辉光，肉眼与关掉时完全一致，采样像素也几乎无差。
- **根因**：radial-gradient 的 size 表示**半径**；`120%` 已是画面半宽的 1.2 倍，画面边缘归一化半径只有 0.4~0.6，落在 `transparent` 区间里，光晕全在视口外。
- **解决**：用 `ellipse 50% 50%`（半径=半宽/半高，边缘恰为 100%）再布 stop（60% 透明 → 100% 青 0.24）；配一层 `::before` 暗角（同为 50% 50%）让青色边缘读起来像辉光。
- **预防**：给全屏元素加边缘光/暗角，先让最外沿落在渐变 90%~100% 区间；效果类改动用「注入 CSS 关闭 + 采样边缘像素」做 A/B，别只靠肉眼盯整图。

### [2026-10-29] 从暗色大屏取「主色」不能直接平均
- **现象**：官网首屏要让光晕/页头跟随画面主色，按全图像素平均取色，三段录屏（风电/数据中心/产线）取出来都是近黑的蓝灰，染色几乎无差别。
- **根因**：监控大屏 90% 是深色底，彩色数据只占少量像素，均值被暗底拉平；且原值亮度太低，直接当光晕色会发黑。
- **解决**：48×27 降采样后跳过亮度 <70 与饱和度 <0.35 的像素，按「艳度² × 亮度」加权平均，再转 HSL 统一拉到 S≥0.7 / L=0.62；取色失败（`file://` 污染画布）用 `data-accent` 兜底。实测得到 青(88,203,229) / 紫(138,90,226) / 琥珀(226,174,90)。
- **预防**：取主色先问「主体像素占比」，别对整图求均值；采样色用于 UI 前必须过一层可读性归一化（饱和/明度下限），不要把原始采样值直接写进样式。

### [2026-10-29] 暗角压暗与光晕提亮在同一层会互相吃掉
- **现象**：给首屏案例改成对角角光 / 底部炉火光后，光晕 alpha 提到 0.24~0.32 仍几乎看不见；而上下辉光的版本正常。
- **根因**：暗角 `::before` 与光晕 `::after` 同为 `z-index:3`，暗角在角部/底部压暗 0.40，screen 光晕只提亮 0.24，净效果仍是变暗——光晕被暗角吃掉。
- **解决**：暗角强度跟着光晕位置走——角光/底光主题（dc/line）把暗角降到 0.20/0.24，只有上下辉光的 sea 保留 0.40；三个主题各用一套渐变，不再共用一个 ring。
- **预防**：叠加特效先算「净叠加」而不是看单层 alpha；同层伪元素互相抵消时按主题分别调参，并用「注入 CSS 关闭 + 边缘采样」做 A/B 验证。

## 后端

### [2026-10-29] mock 慢周期变量首帧必须立即推：periodMs/24 可长达数十秒
- **现象**：新生成的演示工程进入运行态后，风速/IT 负载/线速等 mock 量正常，但所有由它们派生的虚拟变量（功率、转速、PUE、节拍）长时间显示 0，约 50s 后才跳成正常值。
- **根因**：`MockSource.run` 与浏览器 `startMock` 只把首次采样排在 `periodMs/24` 之后；20min 周期的慢趋势变量要等 50s。虚拟变量在首个 mock 值到达前求值失败（unknown variable），且不会主动重算，整条级联链停在 0。
- **解决**：两端在启动时**立即 emit 首帧**（hold 保持型仍只推 `defaultValue`），之后按 interval 定时；历史图另加「服务端样本数 vs 本地缓冲点数取多者」兜底。
- **预防**：引入长周期仿真/趋势变量时，验收必须看 **t+3s 首屏**，不能只看 1 分钟后；虚拟变量链路首帧 0 优先怀疑上游 mock/source 首采样时机。

### [2026-10-28] 改初始密码 ≠ 改库内密码：create_admin 幂等不覆盖
- 改 `ADMIN_PASSWORD` 后已存在的 admin 仍是旧哈希（entrypoint 仅用户不存在时创建），登录照旧失败。**处置**：改库内哈希（`reset_admin_password.py` 或 `PUT /users/{id}/password`），并同步 `.env`/`.env.example`/`config.py`/E2E 脚本，否则重建库又回旧值。
- `docker compose exec` **不走 entrypoint**，没有 `PYTHONPATH=/app`：脚本需自行 `sys.path.insert(parents[1])`；Windows 上 `-e PYTHONPATH=/app` 会被 Git Bash 改写成 `D:/Program Files/Git/app`，本地验证加 `MSYS_NO_PATHCONV=1`（Linux 无此问题）。

### [2026-10-26] 一对多广播：序列化一次 + 并发发送
- 每 100ms 合帧对 N 连接各 dumps、慢客户端按 per-conn 超时**串行**拖住同工程 → 广播前序列化一次，`asyncio.gather` 并发发送（连接级锁保帧序），失败逐个摘除。串行 fan-out 会把单点慢连接放大成全房间延迟。

### [2026-10-22] 本地验证 alembic 迁移的 stamp 法
- SQLite 方言无 ALTER 约束能力（0002 即炸），迁移链只面向 PG（CI PG16 冒烟）。验单个迁移：空库 `alembic stamp <prev>` + `upgrade head` 只跑新段；SQLite URL 用 `sqlite+aiosqlite:///C:/绝对路径.db`。

### [2026-10-20] 查询串带敏感值：两层日志都要查
- WS token 走查询串进 uvicorn access log → `--no-access-log`，访问日志由 nginx 输出（token 掩码）。新增查询串敏感端点必查两层日志。

### [2026-10-25] 入池前两道关：质量位传播 + 事件时间/时钟偏差
- **质量位**：派生计算把「输入质量」当一等输入——scope 只收 good；求值失败把虚拟变量转 bad 写回并广播，不静默保旧值（否则断线后继续输出「正常数」）。stale 判定按变量类型分：hold 常量/计算点/订阅型稳态点「没新帧 ≠ 失效」（`_effective_stale_ms` 返回 0 或心跳 touch），否则正确规则会在另一类变量上制造大面积误报。
- **事件时间**：同窗口乱序帧按到达顺序覆盖 → 入缓冲前比 ts、旧帧丢弃。上游未对时/retained 旧消息污染历史与统计 → 偏差门限 `FRAME_TS_MAX_SKEW_MS`（缺省 300s）超限回落 now + 告警去重；外部时间戳一律先过门限再入库。

### [2026-10-25] 链路健康由链路自己证明，不能由业务数据反推
- 订阅型稳态点永不推帧会被误判 stale；MQTT 死了值没变也可能迟报。采集源维护独立 `state/last_ok_ms`（连接/收发/心跳推进），comm_monitor 分型阈值扫描，「sys_comm:<dsId>」报警。
- 三个坑：内存断线集合必须在**写库成功后**更新（失败要重试）；源删空变量走清除分支（否则报警永久悬挂）；快照短暂缺席连续 2 轮才判删除。

### [2026-10-25] 跨网络副作用先持久化再发送；触发/恢复成对设计
- 通知失败重试 3 次即丢、恢复不外发（值班员只知坏不知好）→ `notification_outbox` 落库补发（指数退避、死信、崩溃遗留回收），逐行处理自己兜异常；clear 路径同样外发（不受触发节流限制）。

### [2026-10-25] 克隆实体：身份字段与内容字段分开
- 深拷贝 doc 建新工程不重写 project.id → 保存 422 `project_id_mismatch`。复制操作先列「哪些是身份、哪些是内容」，身份重新生成并重跑不变量校验。

### [2026-10-27] 契约要落到 SQL 投影层验证；JSONB 方言分派
- 「接口不含 X」契约要落到 SQL 投影层喂真数据验证（`load_only` 裁 doc 列；JSONB 只取标量走路径投影）。
- variant 列（`JSON().with_variant(JSONB())`）在**表达式层不切方言**：`col['k'].astext` 炸 AttributeError → 显式 `cast(col, PG_JSONB)` 再取路径；SQLite 单测覆盖不了 PG 分支，必须真 PG（compose/CI）过一遍。

## 部署 / 构建

### [2026-10-29] `up --force-recreate` 会连依赖一起重建；.env 漂移让整站「看起来像挂了」
- **现象**：只为让 nginx 重新渲染模板执行 `docker compose up -d --force-recreate nginx`，结果 postgres/server 也被重建：server 进重启循环（`password authentication failed for user "webscada"`），nginx 因 `host not found in upstream "server"` 反复退出，产品站 80 直接不可达；同时 nginx 端口从 `80->80` 变成 `8088->80`，外网入口（映射到宿主机 80）全军覆没。
- **根因**：① `--force-recreate` 对本次启动的所有服务生效，nginx 的 `depends_on` 把 postgres/server 一起拉起重建；② 服务器 `.env` 被改过（`HTTP_PORT=8088`、`POSTGRES_PASSWORD=webscada123`，像是本地 `.env` 同步上去的），旧容器仍带着创建时的旧环境在跑所以没人发现，一旦重建就暴雷；③ postgres 数据卷里存的还是**初始化时**的旧密码，`POSTGRES_PASSWORD` 只在初始化生效，改 env 不会改库内密码。
- **解决**：`ALTER USER webscada WITH PASSWORD '<.env 现值>'`（本地 socket 走 trust，直接 exec psql 即可）让库与 env 对齐；`HTTP_PORT=80 docker compose up -d --no-deps nginx` 单独重建 nginx；`.env` 的 `HTTP_PORT` 改回 80。
- **预防**：改 nginx 配置用 `up -d --no-deps <service>`，**永远不要**图省事加 `--force-recreate`；重建前先 `docker compose config | grep -A2 published` 看端口解析结果、`grep ^HTTP_PORT .env` 对齐外网映射；改数据库密码类 env 后必须同步 `ALTER USER`，否则「容器配置变了但库没变」。排查时先分辨**谁在返回错误**：`Server:` 头 + `Date: Sat, 31 Dec 2005`（校园网/运营商上网认证网关的 GB2312「该网站无法访问」页）说明是本机出口被拦，不是服务器。

### [2026-10-28] Windows 检出把脚本执行位弄丢：索引 644 + `core.filemode=false`
- **现象**：服务器 `git pull` 后 `./deploy/deploy.sh` 能跑（bash 显式调用），但脚本内 `./scripts/backup.sh` 报 `Permission denied`，升级停在备份步骤。
- **根因**：全部 `.sh` 在 Git 索引里就是 `100644`（Windows `core.filemode=false`，`git add` 记不到 +x），文件系统上靠编辑器/工具恰好给了可执行位，clone 与 tar/zip 解压路径都不可靠。
- **解决**：`git update-index --chmod=+x` 把 10 个脚本改为 `100755`；脚本互调统一 `bash xxx.sh`（不依赖执行位）；`deploy.sh` 前置校验后 `chmod +x scripts/*.sh` 自愈。
- **预防**：新增任何 `.sh` 后查 `git ls-files -s` 首位是 `100755`；跨脚本调用写 `bash "$ROOT_DIR/scripts/x.sh"` 而非 `./x.sh`。`core.filemode=false` 的机器上 `chmod` 不会被 git 记录，别用「本地 chmod + commit」验证。

### [2026-10-20/21/22] 容器构建/运行三课
- **非 root 落盘**：命名卷按镜像内目录属主初始化，镜像没预建就归 root → `mkdir -p /app/uploads && chown appuser` 再挂卷；运行时 mkdir 绕不过属主问题。
- **多阶段构建**：依赖层禁止 `pip install .`（wheel 依赖源码，缺文件被旧缓存层掩盖）；构建异常先 `docker history` / `--no-cache` 排除缓存假象；基础镜像走 `ARG REG_PREFIX` + 国内源，不写死官方源。
- **旁路容器**：ENTRYPOINT 写死启动序且不 `exec "$@"` → 必须覆写 `entrypoint: []`；`compose up -d` 不重建已有 tag 镜像，代码更新后先 grep 运行容器内新符号确认版本再验收。

### [2026-10-22] 面向实装版本写第三方代码（pymodbus 3.16 / asyncua 2.1 实录）
- 约束下界（>=3.9）解析到 3.16：legacy datastore 运行时写恒 DEVICE_BUSY；asyncua 2.x 五处 API 偏差（stop()/to_string()/显式 nodeId 两参/回调签名 DataChangeNotif/动态端口 bserver.port）。

### [2026-10-25] 备份/交付三课
- 备份清单按「数据存在哪」列全（uploads_data/emqx_data 不在库里）；脚本读配置以运行时实际值为准（`docker compose port`），不假设 shell 有 .env；长期容器显式日志轮转（x-logging 20m×5）。
- 离线交付包白名单收集（防带走 certs 私钥）；`docker compose config --no-interpolate` 保留占位；构建期变量（REG_PREFIX/密钥）随包落地，否则目标机 image not found。
- `set -u` 下禁止多变量 `local` 互相引用（参数统一先展开，`b=$((...a...))` 当场 unbound）；部署脚本先用 stub docker/curl 跑通「首装 + 健康失败回滚」两分支。

### [2026-10-26] 官网接入同容器 nginx 三坑

### [2026-10-29] readonly 工程回写不了缩略图：只能改库，且演示数据不随部署走
- **现象**：线上台账三套旗舰案例没有缩略图；本地库有。想「重新生成一次」也没用——`POST /projects/import` 收的 doc 里本来就没有 `project.thumbnail`。
- **根因**：缩略图由编辑器 `refreshThumbnail` 截图后随 `PUT /projects/{id}` 落库，而 readonly 工程服务端一律 403 `PROJECT_READONLY`（[projects.py](../server/app/api/v1/projects.py)）；前端生成的演示 doc 不含缩略图，所以只读后永远补不上。另：演示案例是库内记录，部署不含数据，新库为空。
- **解决**：直接 SQL 写 `doc.project.thumbnail`（`jsonb_set`），按工程名匹配；不动 `revision` / `updated_at` / `pinned`——改 `updated_at` 会打乱置顶内部的排序。跨库搬迁用 `psql -At -c "select format('update ...', ...)"` 在源库生成语句、管道灌进目标库 `psql`，人工拼 SQL 必被 base64 里的引号/反斜杠咬。
- **预防**：新增「只读」类工程先问「哪些字段本来靠保存链路回写」——缩略图、历史预置、模板截图都属此类，只读后要有旁路（导入时带图 / 运维 SQL / 允许写 thumbnail 的专用端点）。验收缩略图看卡片实际呈现，别看库里有字段。

### [2026-10-29] `.gitignore` 只写注释不写规则：`.env` 被当普通文件提交
- **现象**：`.gitignore` 里写着「本地环境与密钥（.env 不入库，模板见 .env.example）」，但下面没有任何 `.env` 规则。结果根 `.env`（含真实 `JWT_SECRET` / `DATASOURCE_SECRET` / `ADMIN_PASSWORD`）与 `deploy/website/.env` 一直被跟踪，并已推到远端。
- **根因**：把「打算这么做」写成了注释，误当成已经生效的规则；`git ls-files | grep .env` 从未检查过。开源前体检才暴露。
- **解决**：补 `.env` / `.env.*` / `!.env.example` / `deploy/website/.env` 规则，`git rm --cached` 停止跟踪，再用 `git filter-repo --invert-paths` 从全部历史剥离（同步剥离仍在历史里的 `docs/assessment`、`docs/superpowers`）。
- **预防**：判断「某类文件不入库」只看 `git ls-files` 的结果，不看 `.gitignore` 注释；开源/交付前跑一次「历史上出现过的路径 ∩ 当前忽略规则」=`git log --all --pretty=format: --name-only --diff-filter=A | sort -u` 再对规则匹配。`filter-repo` 会 `reset --hard`，被跟踪的 `.env` 会从工作区消失——先 `cp` 到仓库外备份，或先 `git rm --cached` 再重写。

### [2026-10-29] `npm run build` 全绿 ≠ CI 全绿：门禁脚本不在 build 链上
- **现象**：开源首推后 GitHub CI 的 web job 红灯，step 是「视觉令牌门禁」，报 `ProjectsView.vue` 两处硬编码色值；本地 `npm run build` 却是全绿——因为 `build` 只跑 `vue-tsc + vite build`，`check:tokens` 是独立脚本，CI 才串起来。
- **根因**：`.github/workflows/ci.yml` 的 web job 比本地 `build` 多一步；本地验收按 `npm run build` 口径执行，没对齐 CI 步骤清单。
- **解决**：`rgba(20, 33, 46, 0.1)` → 新增令牌 `--ws-shadow-card-hover`；`rgba(255, 255, 255, 0.88)` → 新增 `--ws-panel-a88`（`theme.ts` 用 `alpha(v['--ws-panel'], 0.88)` 派生，深色主题自动跟随）；同步 `--update` 缩减基线 2 键。
- **预防**：本地验收口令 = 「`bash` 照着 `.github/workflows/ci.yml` 的 step 逐条跑」，而不是「跑一下 `npm run build`」。新增门禁脚本时同时提供 `npm run check:<x>` 并在 README/CLAUDE.md 写明，让本地有对齐入口。
